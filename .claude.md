# MX Runbook Monitor — Claude Development Guide

## Project Overview

**MX Runbook Monitor** is a lightweight, zero-infrastructure monitoring tool for production go-live events. It provides real-time task tracking, status exports, and comment management without requiring external infrastructure.

**Tech Stack:**
- **Frontend:** Vanilla JavaScript (ES6+), HTML/CSS — no frameworks
- **Backend:** Node.js HTTP server (embedded in `electron-main.js` or `_serve.js`)
- **Desktop:** Electron (v34.5.8) for standalone Windows app
- **Data Adapter:** Python (Excel/CSV → JSON schema conversion)
- **Testing:** Vitest (JavaScript unit tests)

---

## Quick Start — Build & Run

### Development Mode
```bash
npm install                    # Install Node dependencies
node _serve.js                 # Start dev server on http://localhost:8090
npm run electron               # Launch standalone Electron window
npm test                       # Run JavaScript tests
```

### Production Distribution
```bash
npm run dist                   # Build: dist-electron/win-x64/ folder (~181 MB)
npm run dist:zip               # Build + zip to dist-electron/MXRunbookMonitor-win-x64.zip
```

**Result:** Double-click `dist-electron/win-x64/MX Runbook Monitor.exe` to launch (no npm/Node.js required to run).

### Data Conversion (Python)
```bash
cd adapter
python convert.py --source data.xlsx --mapping mapping.yml --output runbook.json
python convert.py --auto-detect --source data.xlsx  # Suggest column mapping
```

## Key Concepts

### Schema: Runbook JSON Structure

**Core (required):**
```json
{
  "Category Name": [
    {
      "task": "string",
      "status": "Not Started|In Progress|Completed|Blocking|Unneeded",
      "startTime": "YYYY-MM-DDTHH:MM:SS or null",
      "endTime": "YYYY-MM-DDTHH:MM:SS or null",
      "item": "string or null",
      "assignee": "string or null"
    }
  ]
}
```

**v2 Extensions (optional):**
```json
{
  "taskId": "string or null",           // Task identifier (e.g. "TASK-001")
  "system": "string or null",           // Impacted system (e.g. "MX", "SWIFT")
  "party": "Client|Murex|Joint or null", // Responsible party
  "comment": "string or null",          // User-added notes (edited in dashboard)
  "estimatedEnd": "YYYY-MM-DDTHH:MM:SS" // Original planned end (never edited)
}
```

**Metadata:**
```json
{
  "_issues": [
    {
      "category": "string",
      "index": 0,
      "severity": "error|warning",
      "message": "description"
    }
  ],
  "_health": "Green|Amber|Red"
}
```

### Date Handling in Excel Import

**Mapping file option:**
```yaml
category_date_format: "DD Month YYYY"    # Output format: "10 April 2026"
category_date_source: "YYYY-MM-DD"       # Source format in Excel
runbook_date: "2026-04-09"               # Anchor for time-only cells
```

**Parser behavior:**
- Excel **date cells** → parsed as `datetime` by openpyxl
- Excel **time-only cells** → combined with `runbook_date` anchor
- String placeholders (`"hh:mm"`, `"?"`, `"TBD"`) → discarded as `null`
- Categories sorted chronologically; "Uncategorized" / `default_category` always last

### No-Change Files & Contracts

**Do NOT modify without team review:**
- `runbookDashboard.html` — HTML structure is consumed by exporters (Gantt, email, canvas)
- `dashboard/app.js` — State dispatcher; changes affect all actions
- `adapter/schema.py` — Validation contracts; changes break compatibility

**Safe to modify:**
- CSS (inline or in `theme.js`) — styling only
- Dashboard actions/selectors — business logic
- Exporters — output formatting
- Parser mappings — column name changes

## Important Notes for Claude

### When editing dashboard code:
- **State immutability:** All changes go through `actions/` → `state.js`. Never mutate state directly.
- **Null safety:** Always check `task`, `item`, `category` for null before accessing nested properties.
- **Escape HTML:** Use `selectors.escapeHtml()` before rendering user-supplied text (comments, assignees).
- **Timezone:** Store times as local `YYYY-MM-DDTHH:MM` (no UTC conversion). The dashboard UI displays in user's timezone.

### When editing adapter code:
- **Excel quirks:** openpyxl returns datetime(1900, 1, N, ...) for post-midnight times; see `_resolve_time()` for handling.
- **Lazy imports:** `autodetect.py` is only imported when `--auto-detect` flag is used; don't import at top-level if it can fail.
- **Error messages:** Catch `PermissionError` (Excel locked) and `ValueError` (bad input) with user-friendly messages to stderr.

### When building the Electron app:
- **No signing required:** Custom `_electron-dist.js` avoids winCodeSign issues. Just runs on any Windows x64.
- **Asset inclusion:** `_electron-dist.js` copies app files to `resources/app/`. Update the `APP_INCLUDES` list if adding new folders.
- **Icon:** Currently using Electron default icon. To customize, add `.ico` file and reference in `_electron-dist.js`.

## Common Issues & Fixes

| Issue | Cause | Fix |
|-------|-------|-----|
| "Cannot open Excel file" | File locked in Excel | Close Excel, re-run `convert.py` |
| "category_column not found" | Column name mismatch in `mapping.yml` | Check exact column header in Excel sheet |
| Timezone off by 1 hour | UTC conversion in stored times | Use local time format `YYYY-MM-DDTHH:MM` (no `toISOString()`) |
| Null appears as text in UI | Missing `escapeHtml()` or null guard | Add null check + use `escapeHtml()` |
| Electron window won't open | Port 8090 already in use | Change port in `electron-main.js` or stop conflicting process |
| `npm run dist` hangs | Temp folder permissions (OneDrive) | Delete `dist-electron/` and retry |
